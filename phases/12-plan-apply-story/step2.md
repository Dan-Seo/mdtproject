# Step 2: refute-doc-migration — 검증 전용 스텝

**이 스텝은 구현이 아니다. 고치지 마라.** 아래 주장들을 **반증하라.**

이유: 커밋 `41a117c`·`034b801`은 Claude가 직접 쓴 것이고, 이 레포의 규약은
「만든 쪽이 자기 것을 승인하지 않는다」다. 고치라고 하면 검증자가 다시 구현자가 되어
교차가 무너진다. **어긋난 것을 찾으면 그 자리에서 `error`로 두고 무엇이 어긋났는지 적어라.**
어긋난 것이 없으면 그때만 `completed`다.

「돌려봤다」·「읽어봤다」는 검증이 아니다. 각 항은 **틀렸을 때 실패하는 방법**으로 확인하라.

## 대상 커밋

```
git show --stat 034b801   # 감사 보고 2건을 docs/reports/로
git show --stat 41a117c   # CLAUDE.md 이력 두 절 이관 + 지시 2건
```

이관 전 원본은 `git show d1db0cc:CLAUDE.md`다.

## 반증할 주장

### A. 내용이 하나도 사라지지 않았다

주장: `d1db0cc:CLAUDE.md`의 「## 마일스톤 현황」 절 본문이 `docs/MILESTONES.md`에,
「## 열린 리스크」 절 본문이 `docs/RISKS.md`에 **한 글자도 빠짐없이** 들어 있다.

반증 방법: 원본에서 두 절을 잘라내 새 문서와 대조하라. `in` 포함 검사만 하지 말고
**원본에만 있는 줄이 있는지**를 세어라(있으면 그 줄을 전부 적어라).
`## ` 제목 줄과 새로 붙인 머리말은 차이로 세지 않는다.

### B. CLAUDE.md에 남은 요약이 옮긴 본문과 어긋나지 않는다

주장: 새 CLAUDE.md의 리스크 표 14행·마일스톤 표 11행의 **상태 칸**이
`docs/RISKS.md`·`docs/MILESTONES.md`의 실제 서술과 같다.

반증 방법: 행마다 근거 문장을 원문에서 찾아 대조하라. **특히 아래를 의심하라** —
요약은 지어내기 쉬운 자리다.

- `R7`을 「대부분 해소」로, `R9`를 「부분」으로, `R14`를 「해소」로 적었다.
  원문이 그렇게 말하는가? **잔여 항목이 요약에서 사라지지 않았는가?**
- `R6`을 「열림」으로 적고 「사람의 독립 검토가 있어야 닫힌다」고 했다.
- 마일스톤 표에서 `M3c`·`도면 인식`·`부재 확장`·`일본 고유 형태`를 「진행 중」으로 적었다.
  원문의 「남은 것」이 요약의 「남은 것」 칸과 같은가?
- **원문에 있는데 표에서 통째로 빠진 리스크나 마일스톤이 있는가?** (R1~R14 중 결번 확인)

한 행이라도 어긋나면 `error`다. 어느 행이 어떻게 어긋났는지 원문 인용과 함께 적어라.

### C. 두 지시의 수치가 근거 문서와 일치한다

새 CLAUDE.md 「개발 프로세스」의 두 줄이 이 수치를 인용한다:

| 인용된 수치 | 어디서 왔다고 하는가 |
|---|---|
| 툴 호출 메시지 10,682건 중 10,681건(100.0%)이 단일 호출 | `docs/reports/TOKEN-AUDIT-2026-08-25.md` |
| 툴 호출 회당 $0.18 | 〃 |
| `TaskOutput` 회당 평균 7,831자 | 〃 |
| `scripts/execute.py:256`이 `capture_output=True` | 코드 |
| `scripts/execute.py:46`이 `\r` 스피너 | 코드 |
| `scripts/execute.py:342`가 flush 없는 `print` | 코드 |

반증 방법: 앞 셋은 보고서에서 그 숫자를 **찾아라**(없거나 다르면 `error`).
뒤 셋은 **그 줄 번호를 직접 열어** 확인하라 — 줄이 밀려 다른 코드를 가리키면 `error`다.

### D. codex 쪽 주입량 주장이 맞다

커밋 `41a117c`의 메시지는 「이 이관이 codex 쪽에는 절감이 아니고 주입량이
72,397 → 73,773토큰으로 **오히려 1,376 늘었다**」고 적는다.

반증 방법: `scripts/execute.py`가 무엇을 주입하는지 코드로 확인하고(비재귀 glob인가?),
`AGENTS.md` + `docs/*.md`의 현재 합을 직접 재라. 커밋 전 값은 `git stash` 없이
`git show <sha>:<path>`로 재라 — **워킹 트리를 건드리지 마라.**
토큰 환산은 문자수÷1.67이다(보고서의 근사와 같은 방식). 커밋 메시지가 절감이라고
과장했거나 수치가 다르면 `error`다.

### E. 동기화 가드가 실제로 걸린다

주장: `AGENTS.md`는 `CLAUDE.md`의 사본이고 `tests/docs/guardrail-sync.test.ts`가 그것을 지킨다.

반증 방법: **가드가 반증 가능한지** 보아라. `AGENTS.md` 본문 한 줄을 흔들면
그 테스트가 실패하는가? (확인 뒤 반드시 되돌릴 것.) 흔들어도 통과하면 가드가 없는 것이므로 `error`다.

```
npx vitest run tests/docs/guardrail-sync.test.ts
```

### F. 남은 링크가 전부 살아 있다

주장: 새 CLAUDE.md가 가리키는 `docs/MILESTONES.md`·`docs/RISKS.md`·
`docs/reports/TOKEN-AUDIT-2026-08-25.md`가 실재한다.

반증 방법: 새 CLAUDE.md 안의 백틱 경로를 **전부** 뽑아 존재 여부를 확인하라.
이관으로 깨진 것이 하나라도 있으면 `error`다.

## 하지 말 것

- **아무것도 고치지 마라.** 문서도 코드도 커밋도. 이 스텝의 산출물은 판정 하나다
- 어긋난 것을 「사소하다」고 넘기지 마라. 넘길지는 사람이 정한다
- E의 뮤테이션 말고 다른 파일을 수정하지 마라. E의 뮤테이션도 반드시 되돌려라
- 새 테스트를 만들지 마라 — 이 스텝은 검증이지 구현이 아니다
