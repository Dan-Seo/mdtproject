# Step 6: input-panes

좌측 두 페인을 채운다. 평면 에디터(스팬 입력 → 격자 자동 생성 → 클릭 선택)와 부재 단면일람 테이블이다. 이 둘이 M1 관통 경로의 **입력**이다.

먼저 아래 파일들을 읽고 프로젝트의 아키텍처와 설계 의도를 파악하라:

- `/docs/ADR.md` — ADR-004(DWG 인식 없이 간이 평면 입력), ADR-012(主筋·帯筋은 입력이며 제품이 바꾸지 않는다), ADR-005(柱·大梁만)
- `/docs/PRD.md` — §핵심 기능 1

이전 step에서 만들어진 코드를 꼼꼼히 읽고, 설계 의도를 이해한 뒤 작업하라.

## 작업

**TDD로 진행하라.** 컴포넌트마다 테스트 파일을 먼저 만들어라(TDD 가드가 차단한다).

### 1. 평면 에디터 — `src/components/plan/`

DESIGN §2의 좌측 상단 페인이다.

```
平面エディタ  [2FL][RFL]                    ← 페인 헤더 38px + 층 탭
     ○X1    ○X2    ○X3
 ○Y3 ─┼──G1──┼──G1──┼─
      │      │      │
 ○Y2 ─┼──G2──┼──G2──┼─
      │      │      │
 ○Y1 ─┼──G1──┼──G1──┼─
     6000   6000                            ← 스팬 치수
```

**입력 방식은 스팬 수치 입력이다.** X 스팬 배열과 Y 스팬 배열을 표로 편집하면 격자가 다시 그려지고, 교점에 柱, 격자선에 大梁이 자동 배치된다. **개별 부재를 클릭해 추가·삭제하는 편집기는 만들지 마라** — M1 범위 밖이다.

- 스팬 편집: 행 추가/삭제/값 변경. `updateProject`로 스토어에 반영한다
- 렌더: SVG. 격자 교점에 柱 사각형, 격자선에 大梁 선, 각 부재에 符号 라벨, 스팬 치수 표기
- 클릭: 부재를 클릭하면 `selectMember(memberId)` → `sel` 갱신. 선택 표시는 채움 `rgba(245,78,0,.05~.14)` + 테두리·글자 `--color-primary`(DESIGN §3.1)
- 층 탭: `Story` 목록으로 탭을 만든다. `sel`이 바뀌면 그 부재의 층으로 **자동 전환**된다(step 5의 스토어 액션이 이미 처리한다면 UI는 `activeStoryId`를 따라가기만 하면 된다)

**격자·부재 생성 로직은 순수 함수로 분리해 `src/components/plan/`에 두고 테스트하라.** SVG 컴포넌트 안에 섞으면 테스트가 어려워진다. 도메인 규칙이 아니라 화면 배치 로직이므로 `src/domain/`에 넣지 마라.

### 2. 단면일람 테이블 — `src/components/section/`

DESIGN §2의 좌측 하단 페인이다.

```
部材断面一覧
符号  断面      主筋      帯筋
C1   800×800  12-D25   D13@100
G1   400×750  ...      ...
```

- 柱 행: `符号` / `断面 b×d` / `主筋 {count}-{size}` / `帯筋 {size}@{pitch}` / `Fc` / `grade`
- 大梁 행: `符号` / `断面 b×せい` / `主筋 上{topCount}-{size} 下{bottomCount}-{size}` / `あばら筋 {size}@{pitch}` / `Fc` / `grade`
- **전부 편집 가능해야 한다.** 이 값들은 사용자 입력이고 제품이 바꾸지 않는다(ADR-012)
- 편집하면 `updateProject`로 스토어에 반영되고, 파생 계산(`useTakeoff`)이 다시 돌아 내역서·3D가 갱신된다
- `size`는 `BarSize` 유니온이므로 자유 입력이 아니라 선택으로 받는다

**단면일람이 M1 입력량의 대부분이다.** ADR-012의 트레이드오프가 「사용자가 단면일람을 전부 입력해야 하므로 입력량이 늘어난다 — 이것이 UX 리뷰의 최우선 측정 대상」이다. 입력 칸을 불필요하게 늘리지 마라.

### 3. 선택 상태 연동

- 평면에서 부재 클릭 → `sel` 갱신 (DESIGN §3.1 표 1행)
- 단면일람에서 행 클릭 → 그 符号의 대표 부재로 `sel` 갱신
- `sel`이 외부(step 7의 내역서)에서 바뀌어도 평면·단면일람이 강조를 따라가야 한다

테스트에는 최소한 아래가 포함되어야 한다:

- X 스팬을 `[6000, 6000]`으로 두면 X 교점이 3개 생성
- 스팬을 추가하면 柱·大梁 개수가 그에 맞게 늘어난다
- 부재 클릭이 `selectMember`를 호출하고 `sel`이 갱신된다
- 단면일람에서 `主筋 count`를 12→10으로 바꾸면 `Project`가 갱신된다 (제품이 값을 되돌리지 않는다는 회귀 테스트)
- 층 탭 전환이 `activeStoryId`를 바꾼다

## 금지사항

- **DWG/DXF 업로드·도면 인식·IFC 입력을 만들지 마라.** 이유: ADR-004. 검증용 실도면이 없어 노력으로 해결되지 않는 문제다.
- **부재 개별 배치 편집(추가·삭제·이동)을 만들지 마라.** 이유: M1 범위 밖이다. 스팬 수치 → 격자 자동 생성까지가 이번 범위다.
- **主筋 本数나 帯筋 피치를 UI가 자동 계산·보정하지 마라.** 이유: 입력이지 산출이 아니다 (ADR-012). 제품이 구조설계 책임을 지지 않는 경계가 여기다.
- **콘크리트·거푸집 물량 입력란을 만들지 마라.** 이유: 철근만이다 (ADR-005).
- **격자·부재 생성 로직을 `src/domain/`에 넣지 마라.** 이유: 화면 배치 로직이지 규준 도메인이 아니다.
- **평면 데이터를 서버로 보내는 코드를 만들지 마라.** 이유: CRITICAL — 모든 계산은 브라우저에서.
- 기존 테스트를 깨뜨리지 마라.
