# Step 7: takeoff-pane

우측 하단 물량 내역서를 만든다. **이 제품의 산출물이 눈에 보이는 곳이고, 신뢰 장치(出典 칩·inferred 경고)가 사는 곳이다.**

## 작업

**TDD로 진행하라.** 컴포넌트마다 테스트 파일을 먼저 만들어라.

### 1. 12열 테이블 — DESIGN §4를 그대로

`thead`는 sticky. 열 순서와 정렬을 바꾸지 마라.

| # | 열 | 정렬 | 비고 |
|---|---|---|---|
| 1 | 鉄筋 | 좌 | inferred면 이름 옆 crimson 경고 삼각형 |
| 2 | 径 | 우 | `D25` |
| 3 | 形状 | 좌 | 32×18 SVG 아이콘 — `straight` / `hook90` / `hoop` 3종 |
| 4 | 長さ (m) | 우 | **소수 3자리** |
| 5 | 本数 | 우 | 부재 1개당 |
| 6 | 箇所 | 우 | 그룹 내 부재 수 |
| 7 | 総延長 (m) | 우 | `長さ × 本数 × 箇所` |
| 8 | kg/m | 우 | 단위질량, muted |
| 9 | 設計数量 (kg) | 우 | |
| 10 | **所要数量 (kg)** | 우 | **좌측 2px 실선 + `canvas-soft` 배경** |
| 11 | 出典 | 좌 | 규준 칩 |
| 12 | 備考 | 좌 | 인라인 입력. 평소 테두리 없음, 포커스 시에만 hairline+배경 |

**10열의 시각적 분리는 장식이 아니다.** ADR-013의 트레이드오프가 「어느 쪽을 발주에 쓰는지 UI가 명확히 구분해야 한다 — 이 혼동은 틀린 값보다 위험할 수 있다」이다. 좌측 2px 실선과 배경을 빼지 마라.

**소수 자릿수 포맷은 여기서 한다.** 도메인은 raw number를 준다(step 4).

### 2. 행 계층 3단 — DESIGN §4

1. **층 행** — `1階` / `2階`. 배경 canvas, 위쪽 hairline-strong, 소계 굵게 (`storySubtotals`)
2. **그룹 행** — `柱　C1  800×800  [9 箇所]`. 선택되면 좌측 3px 오렌지 바
3. **철근 행** — 들여쓰기 30px. 클릭하면 算出式 디스클로저가 아래에 펼쳐짐

합계 행은 위쪽 `2px solid var(--text-ink)` (`grandTotal`).

**M1에서는 柱 행만 나온다.** 大梁 배근은 M3이므로 大梁 그룹 행이 비어 있는 것이 정상이다.

### 3. 算出式 디스클로저 — DESIGN §4.1

철근 행을 열면 mono `<pre>`로 `QuantityLine.formula`를 그대로 보여준다.

```
加工長 ＝ 2×{(800−2×40)＋(800−2×40)} ＋ 2×135°フック余長 6d(78) ＝ 3040
本数 ＝ ⌈(階高 4200 − 上部大梁せい 750) ÷ 100⌉ ＋ 1 ＝ 36
```

**읽는 사람이 표 값을 손으로 재현할 수 있어야 한다.** 산출식을 여기서 새로 만들지 마라 — step 3이 생성한 `formula`를 표시만 한다. 계산 DAG는 MVP 제외다(PRD).

### 4. 出典 칩 — DESIGN §6 (법적 의무)

칩 하나가 규준 하나에 대응한다. 표기는 `{약칭} {조항}` — 예: `標準仕様書 5.3.4`. 조항이 아직 null이면 약칭만 표시한다.

- **클릭 → 원문 URL 새 탭.** `e.stopPropagation()`으로 행 선택과 분리한다
- hover 툴팁 4줄: `라벨 ＝ 값` / `문서명(판) 조항 쪽` / (inferred면) `⚠ 未確認 —` / 주석
- 10px mono, 4px radius, 1px 테두리
- `source.url`이 `null`이면(예: JIS G 3112 미확보) 링크가 아니라 비활성 칩으로 표시하고 툴팁에 미확보 사실을 적는다

**URL 링크를 죽이지 마라.** ADR-003이 이 근거 문서를 고른 이유가 「누구든 클릭 한 번으로 원문과 대조할 수 있다」이다. 링크가 없으면 근거 선택의 이유가 사라진다.

### 5. inferred 경고 — DESIGN §5의 1·2단계

- **1단계**: 철근 행 이름 옆 crimson 경고 삼각형 + 툴팁에 기여한 항목명
- **2단계**: 出典 칩의 테두리·글자가 `--color-error`로 바뀜

전파 규칙은 step 4가 이미 계산한 `QuantityLine.inferred`를 그대로 쓴다. UI에서 다시 판정하지 마라. (3단계 워터마크는 step 9의 내보내기 몫이다.)

### 6. hoverRow 축 — DESIGN §3.2

- 철근 행에 hover → `setHoverRow(line.id)`
- 행에서 벗어나면 `setHoverRow(null)`
- 이 축은 `sel`과 **별개다.** hover가 `sel`을 바꾸면 안 된다

3D 쪽 반응은 step 8이 구현한다. 여기서는 스토어에 값을 넣는 것까지다.

### 7. 그룹 선택 연동

- 그룹 행/철근 행 클릭 → `selectGroup(groupId, 대표 memberId)` (DESIGN §3.1 표 2행)
- `sel`이 외부(평면)에서 바뀌면 **해당 그룹으로 자동 스크롤**된다

## 금지사항

- **出典 칩이나 하단 고지를 제거하지 마라.** 이유: PDL1.0 준거의 법적 의무다 (CRITICAL).
- **inferred 행을 숨기거나 계산에서 빼지 마라.** 이유: ADR-015는 차단이 아니라 경고를 택했다. 숨기면 사용자가 모르고 쓰는 경로가 다시 열린다.
- **UI에서 inferred 여부를 다시 판정하지 마라.** 이유: 판정은 step 4의 도메인이 한다. 두 곳에서 판정하면 갈린다.
- **산출식을 UI에서 다시 만들지 마라.** 이유: 표시값과 계산값이 갈리는 구조가 된다 (DESIGN §10-1).
- **계산 DAG(숫자 클릭 → 전체 계산 경로 역추적)를 만들지 마라.** 이유: MVP 제외다 (PRD). 행 단위 산출식과 출처 링크까지다.
- **철근 경을 색으로 구분하지 마라.** 이유: 색 12개는 읽히지 않는다 (PRD §디자인).
- 기존 테스트를 깨뜨리지 마라.
