# Step 1: width-tie — 表題의 特記에서 幅止め筋을 읽는다

`幅止め筋`은 표 안의 셀이 아니라 **리스트 표제 줄의 特記**에 있다.
리스트 전체에 걸리는 값이라 한 번 읽어 그 리스트의 大梁 후보 전부에 싣는다.
이 step도 **파서만** 고친다.

## 읽어야 할 파일

- `CLAUDE.md` — M3c 항의 幅止め筋 항목(**大梁에만 붙인다** — 1通則3)의 열거에 柱가 없다),
  ADR-012
- `src/lib/import/section-list/parse.ts` — 표제 탐지 로직 (phase 6에서 표제란 오인을 고친 곳)
- `src/lib/import/section-list/types.ts`
- `src/domain/model/member.ts` — `GirderSection.widthTie`(size·pitch)
- `src/rulepack/` — `measure.width-tie.length.addition` (읽기만 하라. 파서는 룰팩을 조회하지 않는다)

## 전제 — 픽스처의 表題 원문 (조사 완료, 다시 조사하지 마라)

표제 줄도 TextItem이 한 글자씩 쪼개져 있고, 기존 표제 탐지가 이미 그 줄을 잡고 있다.
복원된 문자열은 다음과 같다:

- `ojkk-p3` (大梁リスト):
  `大梁リストA1S=1/30,A3S=1/60※幅止筋はD10@1000とする`
- `yokohama-p14` (大梁断面リスト):
  `大梁断面リスト1/30特記なき限り1.巾止筋D10-@10002.中吊り筋受け筋D10-@10003.［］内はｶｯﾄｵﾌの柱面からの寸法を示す。`
- `yokohama-p13` (柱断面リスト):
  `柱断面リスト1/30特記なき限り1.巾止筋D10-@5002.S13はKSS785を示す。3.HOOPの加工方法は溶接型とする。(柱梁接合部は除く。)4.柱梁接合部は□-D13-@100とする。…`
- `yokohama-p13` (小梁断面リスト):
  `小梁断面リスト1/30特記なき限り1.巾止筋D10-@10002.中吊り筋受け筋D10-@1000`

주의할 점 셋:

1. **표기가 둘이다** — `幅止筋`(ojkk)과 `巾止筋`(yokohama). `幅止め筋`처럼 送り仮名가 붙는 표기도 받아라.
2. **柱리스트에도 巾止筋이 있다** (`D10-@500`). **읽지 마라.** 1通則3)이 幅止め筋 設計長さ를
   정하는 열거에 柱가 없어 제품은 大梁에만 붙인다. 柱 후보에 실으면 근거 없는 값이 된다.
3. **`2.` 이후 항목은 지금 모델에 자리가 없다** — `中吊り筋受け筋`·`S13はKSS785`·`HOOPの加工方法は溶接型`·
   `柱梁接合部は□-D13-@100`·`最上階柱頭の主筋は全180°ﾌｯｸ付`. 전부 읽지 마라
   (溶接閉鎖フープ·パネルゾーン帯筋은 ADR-022에서 **만들지 않기로 결정**한 것이다).
   `1.` 번호에 의존해 자르지도 마라 — ojkk는 번호 없이 `※`로 시작한다.

## 작업

TDD로 진행하라.

### 1. 후보 타입에 `widthTie` 추가 — `types.ts`

```ts
  /**
   * 幅止め筋。リスト表題の特記から読む — 表のセルではない。
   * 未定義は「その配筋がない」を意味する (ADR-012)。大梁にだけ載る
   * (数量積算基準 1通則3) の列挙に柱がない)。
   */
  widthTie?: { size: BarSize; pitchMm: number }
```

### 2. 特記에서 뽑기

표제 줄에서 `幅止筋`·`巾止筋`·`幅止め筋`·`巾止め筋` 중 하나를 찾고,
그 **뒤쪽**에서 첫 번째 「径 + ピッチ」를 읽는다. `D10@1000`(ojkk)·`D10-@1000`(yokohama) 둘 다다 —
**기존 帯筋/あばら筋 피치 정규화 헬퍼를 재사용하라**(`D13-@100`을 읽는 그 함수다). 새로 만들지 마라.

`幅止` 문자열 뒤 **첫 매치만** 쓴다. 뒤에 오는 `中吊り筋受け筋D10-@1000`이 같은 문법이라
전역 매치를 하면 잘못된 값을 집는다.

### 3. 어디에 싣나

- 그 리스트의 `kind: '大梁'` 후보 **전부**에 같은 값을 복사한다.
- `kind: '柱'`·`'対象外'` 후보에는 싣지 않는다. **柱リスト에서는 아예 읽지 마라.**
- 특기가 없는 리스트(kani-p38 등) → 전 후보 `widthTie` `undefined`.
- 정규화 실패 → 채우지 말고 `raw['幅止筋']`에 특기 원문 조각을 남긴다. issue 코드는 새로 만들지 마라
  (리스트 단위 사실이라 셀 단위 issue 대장에 맞지 않는다).

## 테스트

기대값을 리터럴로 박아라:

- `ojkk-p3` 大梁 후보 전부 → `widthTie: { size: 'D10', pitchMm: 1000 }`
- `yokohama-p14` 大梁 후보 전부 → `widthTie: { size: 'D10', pitchMm: 1000 }`
- `yokohama-p13` **柱** 후보 → `widthTie` `undefined` (`D10-@500`을 읽지 않은 것)
- `yokohama-p13` 小梁(対象外) 후보 → `widthTie` `undefined`
- `kani-p38` 후보 → `widthTie` `undefined`
- `yokohama-p14`에서 `中吊り筋受け筋`의 `D10-@1000`을 집지 않았는지 —
  값이 하나뿐이라 값만으로는 구별이 안 된다. **특기 문자열을 잘라 넣은 단위 테스트**로 고정하라
  (`幅止` 뒤 첫 매치 규칙을 직접 겨누는 테스트).

## 금지사항

- **柱의 巾止筋을 읽지 마라.** 이유: 1通則3)의 열거에 柱가 없다. 제품이 柱 幅止め筋을 갖지 않는 것은
  누락이 아니라 결정이다 (ADR-025).
- **特記의 나머지 항목을 읽지 마라.** 이유: 溶接閉鎖フープ·パネルゾーン帯筋은 ADR-022에서
  「만들지 않는다」로 닫힌 항목이고, 中吊り筋은 모델에 없다. 읽어도 갈 곳이 없다.
- **번호(`1.`)로 특기를 자르지 마라.** 이유: ojkk는 `※`로 시작해 번호가 없다.
- **표제 탐지 로직을 다시 쓰지 마라.** 이유: phase 6이 표제란 오인·유령 리스트를 고쳐 둔 곳이다.
  읽기만 더하라.
