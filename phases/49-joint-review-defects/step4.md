# Step 4 — uc25가 자기 체크를 실제 관찰로 채우게 한다

step 0이 C5 또는 C6을 `holds`로 판정했을 때 그 항목만 실행된다.

## 문제

`tests/e2e/uc25-joint-review.js`에서

1. `checks.jointCanvas`와 `checks.findingFocus`가 관찰 없이 리터럴 `true`로 놓인다.
2. 페이지 에러 진단(`__uc25Diagnostics`)을 수집하지만 어떤 체크도 그걸로 실패하지 않는다.
3. `schemaVersion` 비교가 양변에 `?? null`이라 필드가 사라져도 통과한다.

## 요구

1. 두 체크를 **그 시나리오가 주장하는 것을 관찰**해서 채운다. 앞선 `waitForSelector`가 이미
   던지니까 true라는 논리는 쓰지 마라 — 체크는 그 자체로 관찰값이어야 한다.
2. 페이지 에러·콘솔 에러가 하나라도 있으면 실패하는 체크를 만든다. 알려진 무해한 항목이 있으면
   **허용목록을 명시**하고 목록에 없는 것은 전부 실패시킨다.
3. `schemaVersion` 비교는 **양쪽에 값이 있어야** 통과하게 한다. 없으면 실패다.

기존 19체크의 의미를 바꾸지 마라. 체크를 늘려도 되지만 줄이지 마라.

## 검증

명령은 `npx dev-browser --browser kijun --timeout 300 run tests/e2e/uc25-joint-review.js`다.
**먼저 `npm run build` 후 `npx next start -p 3000`으로 서버를 띄운다.** dev 서버가 떠 있는 채로
build 하지 마라 — 같은 `.next`를 덮어 화면이 통째로 안 뜨는데 `curl`은 200을 돌려준다.

반증 가능성 — 아래 셋을 실제로 적용해 각각 해당 체크가 실패하는 것을 확인하고 report에 적는다.
1. 접합부 캔버스를 렌더하지 않게 만들면 `jointCanvas`가 실패한다.
2. 페이지에 에러를 하나 던지면 새 진단 체크가 실패한다.
3. 저장 데이터에서 `schemaVersion`을 지우면 해당 비교가 실패한다.

## 금지

- 체크를 통과시키려고 시나리오를 약하게 만들지 마라.
- 카메라 오라클(`cameraFingerprint`)을 픽셀 비교로 되돌리지 마라. 접합부 장면은 겹친 철근 면의
  z-fighting 때문에 같은 프레임을 두 번 그리지 못한다 — 실측 근거는
  `phases/48-joint-review-ui/step8-report.json#/desktop_host_run/repairs/1/measured`에 있다.

## 추가 — C7: 카메라 오라클의 「장님 아님」 가드를 양쪽에 건다

step 0이 C7을 `holds`로 판정했을 때 실행된다.

`perturbViewer`는 드래그 **전** 지문에만 「최소 한 점이 철근을 문다」를 요구하고 **후** 지문에는
요구하지 않는다. 드래그가 접합부를 화면 밖으로 돌리면 다섯 점이 전부 `hidden`이 되고, 그것이
이전 지문과 다르다는 이유로 통과한다 — 카메라가 허공을 보는데 「움직였다」가 성립한다.

요구: 후 지문에도 같은 조건을 건다. 그리고 「달라졌다」를 **철근이 바뀐 점이 하나 이상 있다**로
좁힌다 — 전부 사라진 것은 증거가 아니다.

반증 가능성: 접합부가 화면에서 사라질 만큼 큰 드래그를 주면 Scenario 7이 실패해야 한다.
그 변이를 실제로 적용해 실패를 확인하고 report에 적는다.
