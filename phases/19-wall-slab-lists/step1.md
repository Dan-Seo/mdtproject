# Step 1: 표 형식 壁リスト・スラブリスト 파서 — 골든 먼저

**전제**: step 0이 `refuted`면 구현을 시작하지 말고 이 스텝을 `blocked`로 두고
`blocked_reason`에 「전사 반증 — Claude 인계 대기」를 적어라. 틀린 전사 위에
골든을 세우면 안 되고, 전사 수정은 Claude 몫이다.

## 배경

코퍼스에 리스트 2면이 들어왔다(phase 18): ojkk-p4(壁·スラブ 표 형식),
yokohama-p15(スラブ 표 형식 ＋ 壁 스케치 주기 형식). 전사 정답은
`tests/fixtures/section-import/expected/`의 두 파일이고 step 0이 검증했다.
제품 모델은 이미 있다 — `WallSection`(耐震壁: thickness·layers·vertical·
horizontal)·`SlabSection`(床板: thickness·x/y×top/bottom). 이 스텝은 **파서와
후보 타입만** 만든다. 취입 화면 반영은 step 2다.

## 할 일

1. **`SectionCandidate` 확장** (`src/lib/import/section-list/types.ts`):
   kind에 `'耐震壁'`·`'床板'` 추가. 필드 설계는 기존 관례(평평한 optional 필드,
   해석 불가는 `raw`+빈칸)를 따르되 제약 둘 —
   - 슬래브 방향은 도면 그대로 **短辺/長辺**으로 담아라. X/Y로 바꾸지 마라 —
     배치 전에는 어느 축이 短辺인지 결정할 수 없고, 결정하면 도면에 없는 방향을
     지어내는 것이다. X/Y 대응은 step 2에서 **사용자가** 고른다.
   - 벽은 thickness(mm)·layers(1|2)·vertical{size,pitchMm}·horizontal{size,pitchMm}.
     layers는 셀 괄호의 「シングル」→1, 「ダブル」 포함(ﾀﾞﾌﾞﾙﾁﾄﾞﾘ 포함)→2로
     읽는다. 그 밖의 표기는 결정 불가 — 빈칸+원문.
2. **골든 테스트 먼저 (TDD)**: `tests/section-import/parse.test.ts`의 기존 sweep
   관례(전사 전 셀 대조 ＋ 확정 칸 수 핀)를 두 expected 파일로 확장하라.
   페이지 전체 `parseSectionLists` 출력을 대조한다 — 스코프 밖 리스트가
   `対象外`로 구분되는 것, 예비 빈 행이 후보를 내지 않는 것 포함.
3. **파싱 대상 형식** 셋:
   - ojkk 壁リスト — 가로형(열=符号, 행=断面·縦筋·横筋·開口補強·備考)
   - ojkk スラブリスト — 세로형(행=符号×{上端筋·下端筋}, 열=短辺方向·長辺方向)
   - yokohama スラブリスト — 세로형(행=符号×{上筋·下筋}, 열=短辺方向·長辺方向,
     「全断面」 부표제, タイプ 열). 上端筋/上筋 용어 차를 흡수하라
4. **対象外 판정은 리스트 표제 기준**: 小梁リスト·片持梁リスト·片持スラブリスト·
   耐圧版リスト. 符号 접두(FS·CS)로 정하면 틀린다 — ojkk FS1~4는 스코프 안
   床板이고 yokohama FS51~52는 耐圧版이다. ojkk スラブリスト 안의 CS1~6은
   **備考 「片持ちスラブ」**로 対象外다 (ADR-028).
5. **정직 실패 경로** — 다음은 값을 확정하면 지어내기다. 빈칸+원문으로 남겨라:
   - 교호 배근: ojkk 「D10･D13@200」, yokohama 「D10D13-@200」 —
     `SlabBarRow`는 단일 径이라 표현 불가
   - ojkk EW15의 두께 「100，150」 — 符号 하나에 두께 표기 둘
   - 符号 다중 열 분리(「W10，W15」↔「100，150」)는 **개수가 일치할 때만**
     순서 대응으로 분리한다. 개수 불일치는 분리하지 마라
6. **yokohama 壁リスト(주기형)는 후보 0이 정답이다.** 표제 「壁リスト」가 있어도
   항목 행·값 열 구조가 없다 — 인출선 주기에서 값을 긁어 벽 후보를 만들지 마라.
   지원하지 않는 형식은 정직하게 실패한다 (R10과 같은 취급).
7. `CANDIDATE_ISSUES` 확장이 필요하면 기존 문구 관례로 추가하라
   (예: 교호 배근 미대응을 사용자가 원문에서 확인할 수 있게).

## 하지 말 것

- `src/domain/**`을 수정하지 마라 — 모델은 이미 있다.
- expected 전사 파일을 수정하지 마라. 골든이 실패하면 파서를 고쳐라 —
  정답을 고치는 것은 Claude와의 합의 없이는 금지다. 정답이 틀렸다고 판단되면
  `blocked`로 멈추고 사유를 적어라.
- 기존 柱·大梁 파싱 경로의 출력을 바꾸지 마라 — 기존 골든이 보증한다.
- 배근 규준 수치를 쓰지 마라 (이 스텝에는 규준 수치가 등장할 이유가 없다).
- 취입 화면(`src/components/**`)을 건드리지 마라 — step 2다.
- `scripts/execute.py`를 실행하지 마라 — 재귀다.
