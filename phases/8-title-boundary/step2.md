# Step 2: refute-guardrail-sync (검증 전용)

**이 스텝은 구현이 아니다. 반증이다.**

Claude Code가 `AGENTS.md`의 본문을 `CLAUDE.md`에서 통째로 다시 생성했다(커밋 `e44e2e0`).
통째로 다시 생성했다는 것은 **옛 `AGENTS.md`에만 있던 내용이 있었다면 조용히 사라졌다**는 뜻이다.
그것을 찾아라.

이 프로젝트의 규칙이다 — 만든 쪽이 자기 것을 승인하지 않는다(`AGENTS.md` 개발 프로세스,
ADR-015·ADR-023의 「전사자＝승인자는 독립 검토가 아니다」와 같은 원리).
codex가 만든 것은 Claude가 검증하고, **Claude가 쓴 문서는 codex가 반증한다.**

## 가장 중요한 규칙: 고치지 마라

어긋난 것을 찾아도 **고치지 마라.** 고치면 검증자가 다시 구현자가 되어 교차가 무너진다.
찾은 것을 적고 status를 `blocked`으로 두면 Claude가 인계받는다.

- 어긋난 것이 하나도 없다 → `"status": "completed"`
- 하나라도 있다 → `"status": "blocked"` + `blocked_reason`에 **무엇이 어긋났는지**
  (파일·줄·원문을 그대로 인용하라. 요약하지 마라)

어느 쪽이든 근거를 `phases/8-title-boundary/refutation.md`에 남겨라 —
확인한 항목마다 「무엇을 어떻게 확인했고 결과가 무엇인가」 한 줄씩.

## 반증할 주장 셋

### ① 동기화로 잃은 내용이 없다

`git show e44e2e0^:AGENTS.md`가 동기화 **직전** 판이다.
그 판에 있던 내용 중 **지금의 `AGENTS.md`에도 없고 `CLAUDE.md`에도 없는 것**을 찾아라.
있으면 그것은 이 동기화가 삭제한 것이다.

- 표현이 바뀐 것은 손실이 아니다. **사실·수치·규칙이 사라진 것**만이 손실이다
- 옛 판이 더 낡아서 지워진 것(예: 이미 틀린 서술)은 손실이 아니다 — 다만
  「틀렸다」는 판단의 근거가 레포에 있는지 확인하라. 없으면 그것도 적어라
- 헤더 4번째 줄은 Claude가 문안을 바꿨다. 사본 고지의 뜻이 유지되는지만 보라

### ② 가드레일 주입 대상은 정말 `AGENTS.md`와 `docs/*.md`뿐이다

`scripts/execute.py`의 `_load_guardrails()`를 읽고 확인하라.
새로 넣은 규칙 둘이 이 사실 위에 서 있다 — 틀렸으면 규칙 문안이 틀린 것이다.
언제 호출되는지도 보라(기동 시 1회인가, 스텝마다인가). 규칙은 「1회」라고 적고 있다.

### ③ 새로 들어간 규칙 두 줄이 사실과 맞는가

`CLAUDE.md`·`AGENTS.md`의 `## 개발 프로세스`에 두 줄이 새로 들어갔다.

- **교차검증 규칙** — 「phase 7이 전 AC를 통과한 채로 값을 지어내는 경로를 하나 남겼다」고
  적혀 있다. `git log`에서 phase 7의 산출물을 보고 그 주장이 맞는지 보라.
  `npm test`가 통과하는데도 지어내는 경로가 정말 있는가?
- **`next dev` + `npm run build` 함정** — 「`tests/e2e/README.md`에 적혀 있으나
  그 파일은 가드레일 주입 대상이 아니라 codex는 못 본다」고 적혀 있다.
  `tests/e2e/README.md`에 정말 그 내용이 있는가? ②의 결과와 모순되지 않는가?

## Acceptance Criteria

```bash
npm run lint
npm run typecheck
npm test
npm run test:golden
npm run build
```

(이 스텝은 코드를 바꾸지 않으므로 AC는 「내가 아무것도 깨뜨리지 않았다」의 확인이다.
하나라도 실패하면 그 자체가 보고 대상이다 — 이전 스텝이 깨뜨린 것이다.)

## 검증 절차

1. 위 AC 커맨드를 실행한다.
2. 주장 ①②③을 각각 반증 시도하고 `refutation.md`에 결과를 적는다.
3. `phases/8-title-boundary/index.json`의 step 2를 업데이트한다 —
   어긋난 것이 없으면 `completed`, 하나라도 있으면 `blocked`.

## 금지사항

- **찾은 것을 고치지 마라.** 이유: 이 스텝의 존재 이유가 그것이다. 검증자가 고치면
  아무도 그 수정을 검증하지 않게 된다.
- **`AGENTS.md`·`CLAUDE.md`를 편집하지 마라.** 이유: 같다. 반증만 한다.
- **「확인했다」·「문제 없다」로 끝내지 마라.** 이유: 「돌려봤다」는 검증이 아니다.
  무엇을 어떻게 확인했는지가 `refutation.md`에 남아야 한다.
- **어긋난 것이 없을 때 억지로 만들어내지 마라.** 이유: 없으면 없다고 적는 것이 정직한 결과다.
  표현 차이·문체 차이는 손실이 아니다.
