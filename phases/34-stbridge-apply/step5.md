# Step 5: 대장에 ST-Bridge 트랙을 올린다 (손갱신 대장이 코드보다 뒤처져 있다)

**전제**: step 4가 `completed`.

## 배경
`docs/MILESTONES.md`·`docs/RISKS.md`·`CLAUDE.md`의 마일스톤 표는 **손으로 갱신하는 대장**이라 코드보다 뒤처진다. 지금 그 셋 어디에도 ST-Bridge 트랙 행이 없다 — phase 33·34가 통째로 대장 밖에 있다. 대장이 모르는 트랙은 다음 세션이 이어받지 못한다.

**수치를 지어내지 마라.** 이 스텝에 쓰는 모든 숫자는 **직접 센 것**이어야 한다. 「대략」·「약」을 쓰지 말고, 셀 수 없으면 숫자를 쓰지 마라.

## 할 일
1. **`docs/MILESTONES.md`** — 「도면 인식(로컬)」 항목과 나란히 **ST-Bridge 트랙 항목 한 줄**을 더하라. 형식은 step 0 기록 항목 10이 적은 그 파일의 기존 형식을 따른다. 담을 것:
   - 착수일(2026-08-28)과 근거 ADR(ADR-043·ADR-044), phase 33·34.
   - **끝난 것**: `.stb` → 중간표현 → 후보 → 승인 반영. 通り芯 그리드와 階 스택뿐. 전부 브라우저 로컬. 실물 코퍼스 4건(전부 MIT)의 파서 무관 실측 대조가 CI에 상시로 걸려 있다.
   - **하지 않는 것**: 断面(`StbSec*`)·부재 배치·開口·かぶり·定着, .stb 쓰기, 재취입·차분 갱신, 버전 어댑터.
   - **남은 것**: 사용자에게서 온 .stb 0건, ver 2.1 계열 현실 규모 파일 0건, 비직교·원호·방사 通り芯과 `BASEMENT`·`ISOLATION`·`DEPENDENCE` 階는 거부로 남는다.
   - 실측 수치를 하나라도 쓰려면 **직접 세어라**(코퍼스 건수, 픽스처 건수, 사유 코드 개수 등). `STB_ISSUES`·`STB_APPLY_REFUSALS`의 개수는 파일을 열어 세라.
2. **`docs/RISKS.md`** — 새 리스크를 하나 더하라. 번호는 step 0 기록 항목 10이 적은 **가장 큰 R 번호 + 1**이다(레이스가 있을 수 있으니 파일을 다시 확인하고 정하라).
   - 내용: ST-Bridge 코퍼스가 **오픈소스 프로젝트의 테스트 픽스처**이고 사용자에게서 온 파일이 0건이며, RC 배근을 담은 파일은 ver 2.0.1 하나뿐이고 ver 2.1 계열의 현실 규모 파일을 찾지 못했다(GitHub 코드검색 `total_count` 9건이 전부 토이 파일과 생성기). R3(일본 사용자 접점 0)과 결합된 리스크다. 상태는 **열림**.
   - 근거는 ADR-043의 실측 4·트레이드오프와 `tests/fixtures/stb-import/SOURCES.md`다. **그 두 곳에 실제로 적혀 있는 것만 옮겨라.**
3. **`CLAUDE.md`** 마일스톤 표에 행을 더하라 — 「도면 인식(로컬)」 아래에 「ST-Bridge 취입」 행. 상태와 「남은 것」 한 줄. 형식은 기존 행과 같게.
4. **`AGENTS.md`를 `CLAUDE.md`에서 다시 생성하라.** `tests/docs/guardrail-sync.test.ts`가 「AGENTS.md가 자체 헤더 뒤에 CLAUDE.md 본문 전체를 그대로 담는다」를 고정하고 있다. **한쪽만 고치면 codex가 낡은 규칙을 받는다.** 동기화 방법은 step 0 기록 항목 10이 적은 그 테스트의 요구를 그대로 따르라.
