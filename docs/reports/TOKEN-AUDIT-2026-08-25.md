## 3. 처방

### 처방 1 — CLAUDE.md의 「지시」와 「이력」을 가른다

**판정: 「마일스톤 현황」(7,410토큰)과 「열린 리스크」(5,342토큰)는 이력이고, 나머지 3,616토큰이 지시다.**

가르는 기준은 「이 문장이 없으면 세션이 규칙을 어기는가」다.

| 절 | 판정 | 이유 |
|---|---|---|
| 아키텍처 규칙 | **지시 — 남긴다** | CRITICAL 7개가 전부 「~하지 말 것」. 없으면 어긴다 |
| 개발 프로세스 | **지시 — 남긴다** | 하네스 위임·교차검증·TDD·골든 우선. **173커밋 사고를 막는 문장이 여기 있다** |
| 명령어 | **지시 — 남긴다** | 실행 가능한 명령. 448토큰으로 싸다 |
| 마일스톤 현황 | **이력 — 옮긴다** | 무엇이 끝났는지의 기록. 규칙이 아니다 |
| 열린 리스크 | **이력 — 옮기되 목록은 남긴다** | R1~R14의 **내용**은 기록, **존재**는 지시에 가깝다 |

- **예상 절감**: 두 절을 `docs/MILESTONES.md`·`docs/RISKS.md`로 옮기고 링크만 남기면 CLAUDE.md 16,375 → 약 3,600~4,600토큰. 턴당 **약 12,000토큰 절감** = 누적 **$118~122 (3.3~3.4%)**.

- **잃는 것** (이 항목이 이 처방의 핵심이다):
  1. **세션이 「무슨 문제가 이미 알려져 있는가」를 모른 채 시작한다.** R6(stated 승격은 사람 몫)·R10(파서 과적합)·R13(좌우 비대칭)을 모르면 이미 닫힌 분석을 다시 하거나, 더 나쁘게는 **이미 기각된 접근을 다시 제안**한다. 이번 세션에서도 R13·R10·ADR-025/028을 근거로 후보를 **기각**했다 — 그 판단은 컨텍스트에 리스크 대장이 있었기에 가능했다.
  2. **「규칙이 문서에 없으면 세션이 바뀔 때마다 직접 구현으로 흐른다」**는 것이 이 레포에서 실제로 일어난 일이다(2026-08-13 이후 10일 173커밋). 그 사고의 교훈은 「지시를 파일 밖에 두지 말라」이지 「이력을 파일 안에 두라」가 아니므로 **개발 프로세스 절을 옮기는 것은 금지**다. 하지만 이력을 옮기는 것도 같은 실패의 약한 형태를 부를 수 있다 — 링크는 클릭되지 않으면 없는 것과 같다.
  3. 반대 근거 하나: **CLAUDE.md 자신이 이 두 절을 믿지 말라고 적는다** — 「수치는 손으로 갱신하므로 코드보다 뒤처진다. 인용하기 전에 코드로 대조할 것」. 실제로 이번 감사에서 R6의 「198행 transcribed」가 실측 237과 어긋났다. **매 턴 12,752토큰을 내면서 신뢰할 수 없다고 명시된 정보를 나르고 있다.**

- **적용 방법** (제안까지다 — 이 프롬프트의 범위 밖이라 실행하지 않았다):
  1. `docs/MILESTONES.md`·`docs/RISKS.md` 신설, 두 절을 통째로 이동.
  2. CLAUDE.md에는 **제목 줄만** 남긴다 — `R1~R14 목록(한 줄씩) + 「내용은 docs/RISKS.md」`. 리스크의 **존재**는 지시이므로 지운다면 (1)의 손실이 그대로 온다. 한 줄 × 14건 ≈ 700토큰이면 12,752 중 12,000을 줄이면서 「무엇이 열려 있는지」는 남는다.
  3. `AGENTS.md`도 같이 고친다 — `scripts/ci/`의 동기화 가드가 있으므로 한쪽만 고치면 CI가 잡는다.
  4. **개발 프로세스·아키텍처 규칙·명령어는 건드리지 않는다.**

### 처방 2 — 파일 통째 읽기를 grep·범위 읽기로 바꿀 자리

**판정: 바꿀 자리가 거의 없다. 이미 하고 있다.**

- `Read` 983회 vs `Bash`(grep·sed -n·cat 포함) 5,968회 — 탐색은 이미 압도적으로 셸 쪽이다.
- 통째 재읽기는 161 세션에서 108회, 최대 5회(§1.4).
- `Read` 회당 평균 2,892자(≈803토큰)는 「전문 읽기가 습관」이라기엔 작다.

- **예상 절감**: 통째 재읽기 108회를 전부 없애도 ~87k 토큰. 증폭을 넉넉히 쳐도 **1% 미만**.
- **잃는 것**: 범위 읽기로 바꾸면 맥락을 놓쳐 재읽기가 늘 수 있다 — 지금 수치가 낮은 이유가 「필요할 때 전문을 읽어서」일 가능성이 있고, 이 데이터로는 구분되지 않는다. **미측정.**
- **적용 방법**: 별도 조치 없음. 다만 상위 항목인 `phases/*/index.json` 재읽기(9회)는 하네스 진행 확인이므로 `python3 -c "import json;print(...)"`로 **status 줄만** 뽑으면 회당 ~1.5k → ~100토큰이 된다. 절감은 작지만 공짜다.

### 처방 3 — 긴 출력에 거는 필터

**판정: 필터를 걸 명령은 정해져 있고, 이미 대부분 걸고 있다.** §1.5의 상위 10건 중 Bash 출력은 1건뿐이다.

| 명령 | 현재 | 걸 필터 | 회당 절감 |
|---|---|---|---|
| `npx vitest run` | `--reporter=dot \| tail -6` 사용 중 | 유지 | — |
| `npm run build` | 전문 | `2>&1 \| tail -25` | ~3k토큰 |
| `npx dev-browser ... run tests/e2e/*.js` | 전문 | `2>&1 \| tail -30` | 미측정 |
| **`TaskOutput`** (하네스 대기) | **전문 7,831자/회** | **§(c) 1위. 아래 참조** | **~7k토큰** |
| `mcp__posthog__exec` | 전문 5,030자/회 | 스키마 조회는 1회로 끝내고 재조회 금지 | ~5k토큰 |
| `browser_console_messages` | 전문 8,261자/회 | `pattern` 인자로 정규식 필터(툴이 지원) | ~7k토큰 |
| `mcp__vercel__list_deployments` | 20건 JSON 11,128토큰 | 필요한 건수만 | ~9k토큰 |

**`TaskOutput`이 폭발 비용 1위인 것은 구조적이다.** CLAUDE.md는 `execute.py`를 백그라운드로 띄우고 90~120초마다 확인하라고 정하는데, 그때 `TaskOutput`이 회당 7,831자를 돌려주고 그 대부분은 **비어 있거나 스피너**다(`execute.py`가 codex 출력을 `capture_output=True`로 삼키므로). 같은 CLAUDE.md가 「진짜 진행 신호는 stdout이 아니라 index.json」이라고 이미 적고 있다.

- **예상 절감**: TaskOutput 25회 × ~7k토큰 = 175k토큰. 증폭 포함 상위 6건만 **$65 (1.8%)**. 전체로는 **미측정**(세션별 남은 턴 수에 따라 갈린다).
- **잃는 것**: 하네스가 `error`·`blocked`를 stdout으로만 내보내는 경우를 놓칠 수 있다. 다만 CLAUDE.md 자신이 status는 `index.json`에서 읽으라고 정하므로 손실은 작다.
- **적용 방법**: 하네스 대기 사이클에서 `TaskOutput` 대신 `python3 -c "import json;d=json.load(open('phases/N-slug/index.json'));print([(s['id'],s['status']) for s in d['steps']])"` 한 줄. 회당 7,831자 → ~150자.

### 처방 4 — codex 하네스로 넘겨 이쪽 컨텍스트를 안 먹게 할 작업 유형

**판정: 「구현」이다. 그리고 이미 CLAUDE.md가 그렇게 정하고 있다 — 지켜지지 않은 것뿐이다.**

500턴+ 세션 10개(전체 비용의 57%)의 툴 구성:

```
Bash:3,642  Edit:1,165  Read:586  PowerShell:336  Write:188  Grep:117  Monitor:76   (합계 6,421)
구현(Edit+Write) 1,353건 = 21%   → 턴 단가 $0.1773 기준 $240
```

상위 2개 세션은 각각 `Edit` 454·389회, 구현 비중 27%다. CLAUDE.md의 「구현은 codex가 한다」가 지켜졌다면 이 1,353턴은 이쪽 컨텍스트에 없었다.

- **넘길 수 있는 유형**: 사양이 확정된 구현(파일 경로·AC·검증 명령이 정해진 것), 기계적 리팩터(중복 제거·이름 변경), 테스트 추가, 반복 수정.
- **넘길 수 없는 유형**: 기획·설계·스텝 사양 작성·**교차검증**(만든 쪽이 자기 것을 승인하지 않는다는 규칙상 검증은 이쪽에 남아야 한다)·사람의 판단이 필요한 결정.

- **예상 절감**: 구현 1,353턴이 전부 하네스로 갔다면 **$240 (6.7%)**. 다만 하네스 감독(`TaskOutput`·`index.json` 확인)에 턴이 드는 것을 빼야 하므로 순절감은 이보다 작다 — **정확한 값은 미측정.**
- **잃는 것**: 왕복 지연. 그리고 하네스가 `blocked`·`error`로 멈추면 인계 비용이 든다(CLAUDE.md에 실제 사례 기록됨 — phase 5 step 2에서 30분 낭비). 사양이 확정되지 않은 탐색적 작업을 넘기면 이 비용이 절감을 넘는다.
- **적용 방법**: 새 규칙이 필요 없다. CLAUDE.md 「개발 프로세스」 첫 CRITICAL이 이미 정확히 이것을 정한다. 이 감사가 더하는 것은 **가격표**뿐이다 — 직접 구현 한 번이 $0.18이고, 긴 세션에서 1,353번이면 $240이다.

## 5. 미확인 / 미측정

- 컴팩션의 순효과 — 인과가 뒤엉켜 이 데이터로 분리 불가(§2 주의).
- 처방 2의 「전문 읽기가 습관이 아니어서 재읽기가 적은 것인지, 재읽기가 적어서 전문 읽기가 정당한지」 — 구분 불가.
- 처방 4의 순절감 — 하네스 감독 턴 비용을 빼야 하는데 phase별 감독 턴 수를 세지 않았다.
- 처방 ②의 상한 — 연속 Bash 쌍 4,865건 중 **의존 관계가 없는 비율**은 자동 판정 불가. 705건(둘 다 읽기전용)은 하한이고, 4,865건 전부를 배치 가능으로 보면 $862(24%)이지만 **이 상한은 방어할 수 없다.**
- `$3,577` 중 Fable-5·Sonnet-5 세션의 성분별 분해 — §1.1은 Opus 단가 통일 근사다.
- 토큰 환산(CJK 1:1, ASCII 3.6:1)은 근사다. 실제 tokenizer로 재지 않았다.
