# 정본 소스와 버전 잠금

규정 수치를 기억으로 채우면 그럴듯하지만 틀린 룰셋이 나온다. 모든 룰 수치는 이 문서에 등록된 소스의
고정된 판에 연결되어야 하며, **등록되지 않은 기억 기반 값은 사용하지 않는다.**

## 확인 상태 구분

| `sourceStatus` | 의미 |
|---|---|
| `CONTENT_CHECKED` | 본문·판·핵심 조항까지 확인 |
| `BIBLIOGRAPHY_ONLY` | 서지(발령·개정·최신판)만 확인. 본문 추출은 아직 |
| `ACCESS_CHECKED` | 공식 진입점 접근만 확인 |
| `PENDING` | 확인 전 |

**이 상태는 독립 검토자의 `verified:true` 승인과 다르다.** AI나 개발자의 확인만으로 활성 룰이 되지 않는다.

## 수량적산기준에서 직접 확인한 정의

스텝 8과 스텝 1 골든 케이스의 출발점이다.

- **6쪽** — 수량은 **設計数量·計画数量·所要数量** 세 가지로 정의된다
- **6쪽** — 所要数量은 「定尺寸法による切り無駄や、施工上やむを得ない損耗を含んだ数量」
  → **정척 절단 로스는 이미 표준 할증률에 포괄**되어 있다. 따라서 절단 조합 최적화는 별개 문제이며
  MVP 범위 밖이다
- **20쪽** — 「鉄筋について、その所要数量を求めるときは、その設計数量の４％の割増を標準とする」
- **13쪽** — 山留め壁(지중연속벽) 철근은 3% 증 / **14쪽** — 말뚝 철근은 3% 증
  → **4%는 躯体 철근 한정**이다. 할증률 룰은 부재 구분을 인자로 받아 골조 이외가 들어오면 값을
  반환하지 않고 실패한다. "모든 철근 4%"로 일반화하지 않는다

## 확인 결과 사용 불가 또는 판 정합성 문제

### 건축공사 표준상세도 (레이와 4년 개정)

https://www.mlit.go.jp/common/001157902.pdf

- 이 PDF는 **3쪽뿐이며 표지와 총칙만 있고 실제 상세도가 없다.** 배근 상세를 여기서 가져올 수 없다
- 2쪽 총칙이 근거를 「公共建築工事標準仕様書 **令和4年版**」으로 명시한다.
  이 프로젝트의 배근 기준은 시방서 **R7**이므로 **판이 어긋난다**
- 스텝 1에서 ① 시방서 R7에 대응하는 상세도 개정판 존재 여부 ② 도면 본편 PDF의 실제 소재를 확인하고,
  없으면 정본 목록에서 제외한다. **확인 전에는 어떤 룰도 이 문서를 근거로 삼지 않는다**

## 구현 전 합법적 원문 확보·판 확인 필요

- **JIS G 3112** 철근콘크리트용 봉강 — 적용 판과 단위질량표를 확정하고 합법적으로 열람 가능한 원문 확보.
  확보 전에는 스텝 4·6·7·8을 완료할 수 없다
- **일본건축학회 JASS 5** 철근콘크리트공사 — 수량적산기준이 보충 적용을 지시하는 항목의 적용 판과
  사용 권한 확인. **H8 결과로 기반 기준이 JASS 5 계열로 바뀌면 확보가 선택이 아니라 필수가 된다**

창소프트 제품군(https://chang-soft.com/products/)은 제품 참고일 뿐 규정 수치의 정본으로 쓰지 않는다.

## 적용 기준은 프로젝트마다 확인한다

공공건축 기준은 국토교통성 관청영선과 관계기관이 **관청시설**에 사용하는 기준이므로, 일본의 모든 민간
프로젝트에 자동 적용되는 보편 기본값이 아니다. 프로젝트마다 `GoverningStandard`에 프로젝트 유형
(공공/민간), 채택 표준과 판, 확인자, 확인일을 기록하고 미확정이면 계산을 차단한다.

- 법정 하한과 법령이 인정한 예외는 사내기준 덮어쓰기와 별도 경로로 다룬다
- 계약도서·구조도·특기시방·채택 표준 사이의 우선순위를 **코드가 해석하지 않는다.** 상충이 있으면
  사람이 판단해 최종 값을 입력하고 그 출처를 `InputRef`로 남긴다
- 도면·특기값이 표준과 다르면 도면이 우선이라는 실무 관행에 따라, 특기값은 항상 입력값으로 들어온다

## 잠금 규칙

스텝 1에서 모든 정본을 `sourceId`, 문서명, 판, 수정일, URL, SHA-256, 확인일로 잠근다.
**같은 URL의 파일 해시가 달라지면 기존 룰을 자동으로 최신이라고 간주하지 않고 재검토 대상으로 표시한다.**

## 검증 코퍼스

`validation-corpus/manifest`에 고정 케이스를 등록한다. 케이스마다 출처 판·쪽·절·표, 입력, 기대값,
반올림 정책, 검토자, 검토일을 기록한다. 기준서에 공식 예제가 없으면 수기 계산 기대값을 만들고
**원문 추출자와 다른 검토자**가 확인한다.

지원 룰 매트릭스의 조건·예외·경계·반올림 분기는 각각 하나 이상의 명명된 케이스에 연결되어야 한다.
**케이스가 0개인 룰은 지원 룰로 표시할 수 없다.**
